# UI audit 32 implementation plan

> Execution: inline, on local branch `fix/ui-audit-32-legacy-ui`; no worktrees.

**Goal:** Resolve A09, A13, A31 and A32 from the pinned [UI audit](../../../reports/ui-audit.md), preserving existing data, permissions and accepted-once mutations.

**Architecture:** Retire legacy rendering branches in shared native controls. Reuse BottomSheetSelect and Reusables AlertDialog. Remove global toast infrastructure and keep read failures in their owning Result or local state.

**Spec:** [Issue 32](https://github.com/SenswaveLabs/Mobile/issues/32), audit sections 10–12. The existing DESIGN.md is merged with the resulting component rules; existing identity and tokens remain authoritative.

## Tasks

- [x] Migrate IconSelector to the compact four-column sheet. Automation keeps all 318 global keys, historical selections and cancellation; virtualize its large palette. Preserve Home/Device catalogs and Dashboard/Radio palettes.
- [x] Migrate ConfirmDialog to native Modal, a named PortalHost and Reusables AlertDialog. Retire Dialog and the legacy SenswaveModal shell; migrate What's New and active typography/loading/legal helpers. Make shared-control defaults use the current system.
- [x] Remove ToastProvider, RootSiblingParent, dependencies and all production emitters. Home distinguishes empty from failed initialization and exposes local Retry, including cached data. User and HTTP failures remain available through Result/HttpResponse; broker status always has local recovery.
- [x] Replace tests that require legacy presentation with behavior checks for exact keys, cancellation, recovery and no global feedback infrastructure. Update AGENTS.md, DESIGN.md and affected guides, removing conflicting instructions.
- [x] Run focused suites plus typecheck, lint and test:poc. Check Android at 320/448/800 dp, both themes and enlarged text; retain screenshots and explicit limitations. Review the whole change.
- Delivery: commit implementation and native evidence, then open a PR targeting next-dev.

## Review focus

- A stale callback cannot choose an icon outside its current catalog or mutate a disabled/read-only form.
- An accepted deletion or save is never repeated by UI migration or recovery.
- Failed or malformed Home reads preserve cached data and never claim the account is empty.
- Late HTTP/session responses cannot emit overlays or dismiss the keyboard.
- Large palettes stay scrollable and preserve exact keys; Back/Close change no selection.

## Decisions and evidence

- Existing issue/audit fully specify the intended UI; reuse current product patterns without a new design interview.
- Repository instruction requires notifying and waiting after failed checks. Characterize the existing defect with passing baseline checks, then verify the updated behavior; do not deliberately make a verification suite fail.
- No backend contract changes or production release are part of this issue.

- Review: one independent whole-change review found removed-home recovery could overwrite a previously selected different home. Fixed by retaining that selection before recovery I/O, with a regression in feedback.test.mjs. Both documentation observations were part of A09 and corrected.
- Native verification found the shared dialog backdrop's Pressable captured content scrolling. A passive animated View fixes the gesture; temporary layout/scroll instrumentation measured a 316 dp body in a 178 dp viewport and offset above 100 dp after an actual drag. Instrumentation and fixture routes are removed before final checks.
