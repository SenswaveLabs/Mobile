# Broker client start design

The user delegated the next screen and authorized UI and UX improvements without additional constraints. This is one routine native screen migration on the current `next-dev` checkout, with no worktree or approval gate. It extends the established Senswave world in `PRODUCT.md`, `DESIGN.md` and the mobile UI policy.

## Intent and approaches

Choose `/dataSource/brokers/startBrokerClient?brokerId=<id>`: it connects the redesigned data-source details to a legacy credential form. Current native evidence is `/tmp/senswave-screen-redesign/start-before.png`; the adjacent reference is `source-details-before.png` in the same directory. The present screen has a prominent blue note, raised fields, a small red switch, quiet primary action, silent required validation and toast-only recovery.

The selected approach reuses the existing single keyboard-aware page and local Reusables-backed controls, with a compact `FormSection`, inline feedback and a checkbox whose value applies on submission. A bottom sheet would complicate keyboard/Back behavior for no task benefit. A multi-step credential flow adds unnecessary navigation. Alternative next screens were Add subscription (smaller but less benefit) and Operations list (valuable but wider loading/pagination/shared-row scope). These are agent decisions within the user's delegated choice.

## Composition and interaction

- Keep the Data Source app bar and native Back; set its existing `DefaultHeader` to `variant="brand"` for this route only.
- One `KeyboardAwareScrollView`, shared `keyboardOffset`, `keyboardShouldPersistTaps="handled"`, themed canvas, 16 dp horizontal gutters, 24 dp top and 16 dp bottom padding. Center a 448 dp maximum-width content area on wide windows. No fixed footer or nested keyboard container.
- Reuse `common/FormSection`: title `Start broker client`, helper `Enter your MQTT broker credentials to connect this data source.`; existing 24/32 dp title, 14/20 dp helper, 24 dp field gaps, 24 dp space before actions.
- Fields are existing `common/Input` and `PasswordInput`, both `variant="auth"`, labeled `Username` and `Password`. Disable capitalization/autocorrect; use username/current-password autofill, Next to focus Password, and Go to submit. Preserve password visibility behavior. No value trimming.
- Follow fields with one full-row checkbox, label `Remember credentials on this device`, helper `Credentials aren't saved on the server. Remember them here for the next connection.` Use the local checkbox's appearance inside one accessible checkbox target with at least 48 dp height; avoid duplicate focus/toggle targets. Changes remain draft until Start.
- `FormSection.actions` holds persistent local Reusables Alert feedback immediately above a full-width amber `common/Button` with `name="Start broker client"`, `type="auth"`. Keep its label while pending. Back stays usable; all content scrolls at 320 dp and 200% font scale. Native targets, including password visibility, remain at least 48 × 48 dp.

## Validation, storage and request lifecycle

- Normalize route arrays by selecting the first `brokerId`, as details already does for `id`. A missing or whitespace-only ID renders local recovery to `/dataSource/list`; mount no form and call neither SecureStore nor HTTP. Key the form by the original nonempty broker ID so separate brokers do not share drafts or accepted-request state.
- Match the existing backend `../next-backend/src/Modules/DataSource/Senswave.DataSources.Application/Brokers/Clients/StartClient/StartClientValidator.cs`: Username and Password are required (whitespace-only is invalid), maximum 256 characters each. Validate on submit, focus the first invalid field and clear only the relevant stale field error while editing. Check whitespace without changing transmitted strings. The former 3-character minimum and 128/64 maxima are obsolete client restrictions; no backend change is needed.
- Retain SecureStore key `brokerClientCredentials-${brokerId}` and JSON `{ username, password }`. Restore only an object containing string values; do not log credentials. Fields, Remember and Start wait while the initial read is pending; Back remains available. A failed read or invalid JSON releases that state, keeps stored data untouched, allows manual entry and shows `Couldn't load saved credentials. Enter them again.` Clear stale action feedback on relevant input changes/new attempts. Late reads after unmount cannot affect another broker or draft.
- Keep existing retention timing: only explicit Start stores exact values when Remember is checked, or deletes that same key when unchecked, before HTTP. A set/delete exception prevents POST, preserves the draft, releases pending and shows `Couldn't update saved credentials on this device. Try again.`
- One synchronous ref lock covers both IME and button submission, including storage and HTTP. During pending storage/HTTP, keep both native fields editable so Android retains the focused input and IME; reject draft changes and feedback clearing in both change handlers while `submitLock.current`, `accepted.current` or `restoring` is true. Remember and repeated Start stay disabled; fields expose pending through `accessibilityState.busy`, without claiming they are disabled. Initial restore and accepted success still disable native fields. Keep `submitBehavior="submit"` on both fields; no forced focus or Keyboard API. POST only `v1/datasources/brokers/${brokerId}/clients` with exactly `{ username, password }`. A rejected result/exception shows `Couldn't start the broker client. Check your credentials and connection, then try again.` above the action, preserves input and permits retry. No toast or keyboard dismissal.
- Latch acceptance before any subsequent work. Only an active route whose latest current home's source matches this broker may call existing `homes.refreshCurrent()` once as best-effort; its `Promise<void>` cannot establish HTTP refresh success. A thrown refresh must not become a failed Start or enable another POST. Do not rewrite the provider.
- On accepted Start, announce `Broker client started.` and navigate Back; with empty history replace `/dataSource/details` using `{ id: brokerId }`. If navigation throws, show `Broker client started. Return to the data source to check its connection.` and a `Return to data source` action that retries navigation only. Late completion after blur never navigates or shows feedback on the destination; refocusing an accepted form resumes return navigation without another POST.

## Boundaries and verification

Preserve source ownership, API contracts, global configuration, existing credentials and unrelated screens. No dependencies, native modules, new provider API, infrastructure, release, icon or backend source changes. Keep `FC` and interface props, `StyleSheet.create()` and `useTheme()` colors. The source caller and its focus reload remain intact.

Add real-handler checks using `tests/nativeComponentHarness.mjs` for validation boundaries, exact values/storage key, restoration failures, duplicate/pending locks, storage/HTTP failures, accepted-once navigation recovery, late completion and route isolation. Include the route in existing global-toast suppression checks and the focused file in `test:data-sources`. Update the AGENTS index, interface and validation guidance in the implementation. Handler tests do not establish native layout, keyboard, Back or TalkBack.

The coordinator verifies the Android flow in both themes, normal/200% text, narrow/short keyboard windows, password visibility, checkbox target, validation, cancellation and return navigation. Use disposable local fixtures for pending/failure/success; do not start, stop or restart the existing external EMQX broker during review. No product data mutation is needed to prove form layout.
